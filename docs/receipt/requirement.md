# 單據處理與管理系統 - 詳細需求與規格說明書

## 1. 概述與目標

WHassistant 為桌面使用者提供一套本地優先（Local-first）的智慧單據/發票掃描、審核與管理系統：

- 支援透過手動拖曳上傳或後台目錄自動監聽匯入單據圖片。
- 利用本地 Ollama 視覺模型（預設 `llama3.2-vision`）進行高精度結構化數據提取。
- 套用業務規則對提取的資料進行標準化與數學校驗。
- 將單據主資訊與明細項存入本地 SQLite 資料庫，並由應用程式統一管理圖片儲存檔案。
- 提供直覺的審核隊列互動、資料線上編輯修正、狀態流轉確認、歷史分頁查詢，以及自動化資料生命週期管理與過期清理功能。
- **全介面繁體中文規範**：本應用程式的使用者皆為繁體中文使用者，前端 UI 介面（導覽列、頁籤、按鈕、表單標籤、表格欄位、狀態徽章、提示訊息、錯誤警告、對話方塊等）必須全部一律使用繁體中文顯示。

## 2. 單據資料模型與標準化規則

### 2.1 單據主表（Header Information）

- `id`: 唯一識別碼（自動遞增主鍵 INTEGER PRIMARY KEY)
- `no`: 工單號 integer unique key,
- `matainer`: 施工人員
- `work_date`: 施工日期（標準 ISO-8601 日期格式 `YYYY-MM-DD`，**逾期計算之唯一核心基準點**）
- `total_amount`: 單據總金額（標準化保留 2 位小數）
- `currency`: ISO 貨幣代碼（如 `USD`, `CNY`, `TWD`, `EUR` 等）
- `image_path`: 應用程式管理目錄下的相對圖片檔案路徑
- `status`: 單據生命週期狀態：
  - `processing`: 辨識或標準化處理中
  - `unconfirmed`: 待確認（已提取資料，等待人工核對）
  - `confirmed`: 已確認（使用者已審核並確認入庫）
  - `failed`: 提取失敗或模型輸出無效（支援重試或手動輸入）
- `payment_status`: 收費狀態（核心生命週期判定欄位）：
  - `unpaid`: 未收費（預設，即便到期亦受保護不可刪除）
  - `paid`: 已收費（超過生命週期保留天數後可被安全清理
- `payment_term_id`: 關聯的收費期限方案 ID（INTEGER，外鍵關聯 payment_terms(id)）
- `due_date`: 應收截止日期（標準 ISO-8601 格式 `YYYY-MM-DD`，**嚴格以「施工日期（work_date）+ 收費期限天數」自動計算**，亦允許使用者手動微調覆蓋）
- `paid_at`: 收費完成時間（標準 ISO-8601 格式，未收費時為 NULL）
- `error_message`: 當狀態為 `failed` 時的具體錯誤原因
- `created_at`: 資料入庫時間（ISO-8601，僅記錄檔案匯入時間，**不作為**逾期計算基準）
- `updated_at`: 最後修改時間（ISO-8601）

### 2.2 業務標準化與校驗規則

1. **日期時間標準化**：精準辨認工單上的「**施工日期**」（主要是辨認民國XXX年XX月XX日或 113/05/20 等格式），統一轉換成 `YYYY-MM-DD` 存入 `work_date`。
2. **數值清理**：剔除貨幣符號（`$`、`¥`、`NT$`、`€` 等）、千分位逗號以及多餘空白，金額均標準化保留兩位小數。
3. **民國年份轉換邏輯**：例如 `民國113年5月20日` 或 `113/05/20`，民國年份加上 1911 轉換為西元年 `2024-05-20`。
4. **應收截止日推算邏輯（施工日期基準原則）**：單據匯入或辨識完成後，**必須以工單上記載的「施工日期（work_date）」作為唯一基準點**，加上收費期限方案之折合天數算出 `due_date`（即 `due_date = work_date + duration_days`）。**絕不可使用軟體系統匯入的 `created_at`**，避免因補掃描、晚匯入或批次匯入造成逾期時間計算偏差。

### 2.3 已處理檔案記錄表（processed_files 表）

專門供「目錄自動監聽」排重使用，防止重複掃描處理相同檔案：

- `id`: 唯一識別碼（自增主鍵 INTEGER PRIMARY KEY）
- `file_path`: 原始檔案的絕對路徑（TEXT NOT NULL）
- `file_hash`: 檔案內容 SHA-256 雜湊值（TEXT NOT NULL UNIQUE），即使檔名更改亦能精確排重
- `file_size`: 檔案大小（INTEGER NOT NULL，單位位元組 bytes）
- `receipt_id`: 關聯生成的單據主表 ID（INTEGER，外鍵關聯 receipts(id) ON DELETE SET NULL）
- `status`: 處理狀態（TEXT NOT NULL，如 `success` 成功、`failed` 失敗、`skipped` 略過）
- `error_message`: 當處理失敗時記錄的錯誤訊息（TEXT）
- `processed_at`: 處理完成時間（TEXT NOT NULL，標準 ISO-8601 格式）

**索引設計**：

- `idx_processed_files_hash`: 在 `file_hash` 上建立唯一索引（UNIQUE INDEX），確保雜湊檢索效率與唯一性。
- `idx_processed_files_path`: 在 `file_path` 上建立普通索引，加速路徑比對。

### 2.4 系統設定表（app_settings 表）

用於持久化儲存使用者配置的各項參數：

- `key`: 設定鍵名（TEXT PRIMARY KEY，如 `ollama_url`、`ollama_model`、`monitor_dir`、`monitor_enabled`、`retention_days`、`default_payment_term_id`）
- `value`: 設定值（TEXT NOT NULL，儲存字串或 JSON 字串）
- `updated_at`: 最後更新時間（TEXT NOT NULL，ISO-8601）

### 2.5 收費期限規則表（payment_terms 表）

用於紀錄多長時間內應該收費的規則方案（如 30d、1m 等）：

- `id`: 唯一識別碼（自增主鍵 INTEGER PRIMARY KEY）
- `name`: 方案顯示名稱（TEXT NOT NULL，如「即期付款」、「月結30天」、「雙月結60天」）
- `duration_code`: 週期代碼（TEXT NOT NULL，如 `0d`、`30d`、`1m`、`2m`、`90d`）
- `duration_days`: 折合天數（INTEGER NOT NULL，供日期加減與逾期運算，如 0, 30, 60, 90）
- `is_default`: 是否為系統預設方案（INTEGER DEFAULT 0，1 代表預設）
- `description`: 備註說明（TEXT）
- `created_at`: 建立時間（TEXT NOT NULL，ISO-8601）

**預載種子資料（Default Seed Data）**：

1. `即期付款`（代碼：`0d`，天數：0 天）
2. `月結 30 天`（代碼：`30d` / `1m`，天數：30 天，預設）
3. `雙月結 60 天`（代碼：`60d` / `2m`，天數：60 天）
4. `季結 90 天`（代碼：`90d` / `3m`，天數：90 天）

## 3. Ollama 視覺提取流程

1. **預設配置**：
   - 介面位址：`http://localhost:11434`
   - 辨識模型：`llama3.2-vision`
2. **結構化提示詞（Structured Output Prompting）**：
   - 採用嚴格的 JSON Schema 提示詞，約束模型直接返回包含保養者（施工人員）、工單號（如 NO.12345678）、施工日期（民國年或西元年）、總計金額等結構化 JSON 資料。
3. **設定與可自訂性**：
   - 使用者可在「系統設定」頁面自訂修改介面位址與模型名稱。
   - 提供「測試連線」功能，檢測 Ollama 連線狀態並列出本地已下載的視覺模型。
4. **容錯與後備機制**：
   - 當 Ollama 離線、連線逾時或模型無法辨識圖片時，單據狀態記為 `failed`，並完整保留已儲存的圖片。
   - UI 介面顯示明確的錯誤原因，並提供：
     - **重試提取**按鈕（重新呼叫 Ollama）。
     - **手動補錄**模式（在圖片對照下直接透過表格手動填寫欄位儲存）。

## 4. 檔案儲存與目錄監聽

### 4.1 應用程式託管圖片目錄

- **跨平台原生標準路徑**：採用 Rust `dirs::data_local_dir()` 自動對應各作業系統的原生標準本機資料目錄：
  - **macOS**：`~/Library/Application Support/whassistant/receipts/images/`
  - **Windows**：`%LOCALAPPDATA%\whassistant\receipts\images\`（即 `C:\Users\<使用者>\AppData\Local\whassistant\receipts\images\`）
  - **Linux**：`~/.local/share/whassistant/receipts/images/`
- **自訂路徑支援**：預設使用上述原生標準目錄，並在「系統設定」中允許使用者依需求自訂變更圖片儲存位置。
- **儲存與防碰撞**：無論是手動拖曳還是目錄監聽匯入的圖片，均複製到該託管目錄，並使用防碰撞唯一檔案名稱儲存（如 `<timestamp>_<hash>.<ext>`），資料庫中僅儲存相對於託管目錄的相對路徑。
- **生命週期同步清理**：當單據在資料庫中被刪除（無論手動刪除還是生命週期過期清理），系統自動同步從磁碟刪除對應的圖片檔案。

### 4.2 目錄自動監聽（Directory Monitor）

- 基於 Rust `notify` 函式庫，在後台非同步監聽使用者指定的資料夾。
- 支援的圖片格式：`.png`, `.jpg`, `.jpeg`, `.webp`。
- **無損策略**：不改動、不移動、不刪除使用者監聽目錄中的原始檔案。
- **排重機制**：使用 SQLite 內部表（`processed_files`）記錄已處理檔案的 Hash/路徑與時間，避免軟體重啟時重複處理。
- 後台偵測到新圖片後自動觸發 Ollama 解析，並將結果以 `unconfirmed` 狀態放入待審隊列。

## 5. UI 介面與互動設計（全繁體中文）

應用程式介面所有文字（導覽、按鈕、表格、對話框、狀態標籤）一律使用繁體中文顯示。整體採用三大功能頁面配置：

### 5.1 【待審單據】頁面（單據審核工作台）

- **拖曳上傳區**：醒目的檔案拖曳區域，文字提示「拖曳單據圖片至此處，或點擊下方按鈕上傳」，包含【選擇圖片檔案】按鈕。
- **待審清單卡片欄**：
  - 橫向或側邊卡片列，列出所有「待確認」與「辨識失敗」的單據。
  - 卡片顯示：單據縮圖、工單號、保養者、建立時間、狀態標籤。
  - 狀態標籤中文顯示：
    - `【待確認】`（黃色標籤，已提取完成等待人工確認）
    - `【處理中】`（藍色標籤，正在執行模型辨識與資料標準化）
    - `【辨識失敗】`（紅色標籤，模型離線、逾時或無法辨識）
- **左右分屏審核器**：
  - **左側（原圖檢視區）**：支援滑鼠滾輪放大、縮小、拖曳平移單據圖片。
  - **右側（資料編輯表單）**：
    - 欄位標籤：工單號、保養者/施工人員、**施工日期**（辨識工單日期並支援民國年轉西元年）、總金額、幣別。
    - **收費期限方案**：下拉選單（預設選取系統預設方案，如「月結 30 天」）。
    - **應收截止日**：嚴格依「**施工日期（work_date）**」自動加算期限天數推導生成，亦提供日期選擇器供使用者手動微調覆蓋。
    - 數學校驗警示：若總計有異常，顯示黃色警告提示文字「金額可能存在不符，請核對原圖」。
- **快捷操作按鈕**：
  - 【確認儲存】：檢查欄位無誤後，將狀態更新為「已確認」並儲存入庫。
  - 【刪除單據】：彈出繁體中文確認對話方塊「確定要刪除此單據嗎？關聯的圖片檔案將一併清除」，確認後刪除記錄與圖片。
  - 【重新辨識】：針對辨識失敗或結果不佳的單據，重新呼叫 Ollama 模型處理。
  - 【手動補錄】：當辨識失敗時，直接在右側表單手動輸入欄位並儲存。
  - 【上一筆】/【下一筆】：快速切換審核下一張單據。

### 5.2 【歷史單據】頁面（單據庫分頁管理）

- **搜尋與篩選列**：
  - 搜尋輸入框（提示字：「請輸入工單號或保養者名稱...」）。
  - 收費狀態篩選下拉選單：【全部狀態】、【未收費】、【已收費】。
  - 施工日期區間選擇器（開始日期 ～ 結束日期）。
  - 【搜尋】按鈕、【重設】按鈕。
- **單據分頁表格**：
  - 欄位標題：`單據縮圖`、`工單號`、`保養者`、`施工日期`、`應收截止日`、`總金額`、`幣別`、`收費狀態`、`建立時間`、`操作`。
  - 收費狀態徽章：`【未收費】`（橘黃色標籤）、`【已收費】`（綠色標籤）。
  - 分頁列：顯示總筆數、當前頁碼，以及【上一頁】、【下一頁】切換按鈕。
- **查看與再次編輯彈窗**：
  - 點擊表格列或【檢視詳細】按鈕彈出詳細視窗，展示完整大圖與單據各項欄位，支援後續修改與【儲存修改】。
- **單據操作**：包含【標記為已收費】/【標記為未收費】、【檢視】、【編輯】、【刪除】按鈕。

### 5.3 【逾期未收單據】頁面（催收提醒專頁）

專門列管所有**收費狀態仍為「未收費」，且「當前日期 > 應收截止日（due_date）」**的單據，避免因逾期而漏收帳款：

- **頂部統計指標看板**：
  - 逾期未收總筆數（例如：`逾期未收：12 筆`，紅色顯著標記）。
  - 逾期未收總金額（例如：`待收總額：NT$ 48,500`）。
- **逾期催收表格**：
  - 欄位標題：`單據縮圖`、`工單號`、`保養者`、`施工日期`、`應收截止日`、`已逾期天數`、`總金額`、`幣別`、`操作`。
  - `已逾期天數`：紅色警告標籤提示（計算方式：`當前日期 - due_date`，例如 `逾期 15 天`）。
- **快捷操作**：
  - 【標記為已收費】：點擊後填入當前時間為收費完成時間，狀態切換為已收費，單據自動移出逾期提醒清單。
  - 【檢視原圖】：快速對照原始施工照片與資訊。
  - 【批次標記已收費】：支援多選後一次性將選取單據標記為已收費。

### 5.4 【系統設定】頁面

- **收費期限規則管理（Payment Terms）**：
  - 規則方案清單表格：方案名稱、代碼（如 30d/1m）、折合天數、是否為預設方案、操作（【編輯】、【刪除】、【設為預設】）。
  - 【新增收費期限方案】按鈕：彈出表單設定方案名稱、週期代碼、折合天數及說明。
- **Ollama 視覺模型設定**：
  - 標籤「伺服器網址」（預設：`http://localhost:11434`）。
  - 標籤「視覺模型名稱」（預設：`llama3.2-vision`）。
  - 【測試連線】按鈕：測試成功顯示「連線成功，模型可正常使用」，失敗顯示「連線失敗：[具體錯誤原因]」。
- **目錄自動監聽設定**：
  - 標籤「監聽資料夾路徑」：顯示當前路徑，附帶【選擇資料夾】按鈕。
  - 標籤「自動監聽狀態」：開關切換【啟用自動監聽】/【停用自動監聽】。
  - 統計資訊：顯示「已自動處理檔案總數：X 筆」。
- **資料儲存路徑**：
  - 顯示當前圖片託管目錄路徑（預設各系統原生 Local 資料目錄），附帶【變更儲存目錄】按鈕。
- **資料保留週期與清理**：
  - 標籤「歷史單據保留天數」：下拉選單提供【30天】、【90天】、【180天】、【365天】、【永久保存】。
  - 說明提示：「僅針對已完成收費的歷史單據進行過期判定；未收費單據受到絕對保護，不論多久均不會被清理。」
  - 【立即清理已收費過期單據】按鈕：點擊後彈出確認對話方塊「預計將清理 X 筆已收費之過期單據及關聯圖片，未收費單據受到安全保護不會被刪除，確定執行？」，點擊【確認清理】即刻執行。

## 6. 資料生命週期、收費防護與定期清理

1. **核心原則與防護機制**：
   - **未收費單據（絕對防護原則）**：資料生命週期的核心目的在於防止漏收帳款。**只要單據處於「未收費」（unpaid）狀態，無論時間多久、即使已經超過應收截止日（due_date），系統絕對不可刪除**！系統自動將逾期未收費單據納入【逾期未收單據】提醒頁面，並在導覽列顯示紅點通知。
   - **已收費單據（安全清理原則）**：只有已完成收費（paid）且自施工日期起算已超過設定保留天數的單據，才視為結案歷史封存，允許系統自動或手動安全清理以釋放磁碟空間。
2. **日期計算與逾期判定基準（施工日期核心原則）**：
   - **基準點規定**：**嚴格以工單上的「施工日期（work_date）」為唯一計算基準點**。絕對不可使用系統檔案匯入時間（`created_at`），以防補掃描、延後批次匯入等情境造成逾期判定失準。
   - **應收截止日推算**：`due_date = work_date + payment_term.duration_days`（亦允許人工微調覆蓋）。
   - **逾期判定**：若 `payment_status = 'unpaid'` 且 `當前日期 > due_date`，即判定為逾期未收單據，逾期天數為 `當前日期 - due_date`。
   - **歷史過期清理判定**：以「已收費（paid）」且 `work_date < (當前日期 - 保留天數)` 為清理條件。
3. **清理觸發時機**：
   - **應用程式啟動時**：
     1. 自檢並自動清理符合「已收費 且 施工日期超過保留期限」的單據與圖片。
     2. 統計目前「逾期未收」單據數量，並更新【逾期未收單據】頁籤之提醒徽章。
   - **後台每日 10:00 排程任務**：
     1. 自動執行過期已收費單據清理。
     2. 更新逾期未收費單據統計與提醒狀態。
   - **手動觸發**：使用者於「系統設定」頁面點擊【立即清理已收費過期單據】。
4. **清理流程（嚴格限制已收費項目）**：
   - 僅檢索滿足 `status = 'confirmed' AND payment_status = 'paid' AND work_date < 過期閾值` 的單據 ID 及關聯 `image_path`。
   - 自磁碟徹底刪除應用程式託管的圖片檔案。
   - 在資料庫交易（Transaction）中串聯刪除單據表記錄。

## 7. 技術架構與選型

- **前端 UI 框架**：Dioxus 0.7 桌面端（`desktop` 特性，採用 Signal 響應式狀態管理、Router 路由、Tailwind CSS 樣式體系）。
- **本地資料庫**：`sqlx`（非同步 SQLite，支援連線池與 Migration 腳本）。
- **檔案監聽**：`notify` 函式庫（跨平台檔案變更監聽，具備防抖與去重邏輯）。
- **HTTP 用戶端**：`reqwest`（啟用 `json` 和 `tokio`，對接 Ollama REST API）。
- **時間與日期**：`chrono`（處理 ISO-8601 標準轉換與留存過期時間運算）。
- **資料摘要**：`sha2`（計算圖片雜湊值用於排重）。
- **跨平台路徑解析**：`dirs` 函式庫（自動適配各作業系統原生標準資料目錄與設定目錄）。
